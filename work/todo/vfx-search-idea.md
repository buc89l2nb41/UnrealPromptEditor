# 아이디어 — 글만 있을 때 설계도를 가져와 look을 고른다

아직 구현하지 않는다. 본선은 [`vfx-loop.md`](vfx-loop.md) **V2** (레퍼런스 이미지). 이 장은 그림 없이 “X 만들어줘”일 때의 보조다.

Editor Prompt 제품은 그대로다. 패널 → MCP → 뷰포트. Cursor 앱 채팅으로 조종하지 않음.

**시작 규칙:** 코드를 고치지 말고 이 파일을 연 뒤 시작 여부를 묻는다. “해” 전에는 웹 검색 손·프롬프트 변경 없음.

---

## 한 줄

검색으로 남의 Niagara 그래프를 재현하지 않는다. “X를 보통 어떻게 짜는지” **전체 설계도**를 다국어로 모아, 합치면 그 방향으로 만들고, 갈리면 유저에게 고르게 한다.

---

## 왜 있는가

글만 있으면 지금 손은 `infer_look` 몇 단어와 Fountain/리본/카드 레시피에 맡긴다. 사람은 튜토리얼을 보고 골격부터 잡는다. 그 감을 힌트로 쓰되, 마켓 팩·영상 노드를 옮기지는 않는다.

레퍼런스 픽셀이 있으면 그 픽셀이 이긴다. 검색이 V2를 덮지 않는다.

---

## 순서

1. **그림이 있거나** 문장에 카드·리본·메시·플립북이 있으면 검색하지 않는다. 픽셀·그 단어로 MCP.
2. **글만** 있고 look이 애매하면 한·영·일 등으로 “X를 어떻게 만드는지”를 찾는다. 영문 키워드를 꼭 넣는다. Niagara 모듈·Epic 템플릿 이름은 영어가 본체다.
3. 종합하는 건 모듈 나열이 아니라 **전체 그림**이다.
   - 골격: 카드 플립북 / Fountain 스프라이트 / 리본 / Fluids 가스 / 메시
   - 층: 불꽃만인지, 연기·불씨를 넣는지
   - 순서: 먼저 실루엣, 그다음 궤적
   - 쓰지 말 것
4. **한쪽으로 모이면** 지금과 같다. Niagara 이름 묻기 → 템플릿 복제 → `generate_png` → spawn/color → 같은 Send에서 컴파일·빨간 NS 고치기.
5. **표가 갈리면** 만들지 않는다. look만 퀴즈하지 않고 **갈래 전체**를 두세 개 짧게 고르게 한다. 예: 플립북 카드 한 장 / 스프라이트 여러 장 / Fluids 가스. 고르면 그때 MCP. “잘 모르겠어요”로 끝내지 않는다.

뷰포트에 올린 뒤는 지금과 같다. 같은 채팅에서 보고 고친다. New Agent는 새 NS다. 검색은 첫 Send의 설계도이고, 이후는 화면이 소스다.

---

## 손이 닿는 범위 (지금)

되는 것:

- `apply_vfx_recipe` look=`card_flipbook` | `card_noise` | `particles` | `ribbon` | `mesh`
- `list_niagara_templates` + `create_niagara_system template=`
- `list_niagara_stack` / `set_niagara_module_input` / `compile_niagara`
- 같은 턴에서 `Compiled FAILED`면 고칠 때까지

아직 약한 것:

- Fluids User Parameter (애셋, 벡터). `set_niagara_float`는 액터·float만
- 5.4 기본 갤러리에 Beam 템플릿 없음 (`Static Beam`은 옛 문서/Content Examples)
- 자동 고르기는 `grid`/`fluid` 이름을 -1000 해서 Fluids를 안 집음

자료가 “Beam Start를 써라”여도 템플릿이 없으면 리본으로 바꾸거나, 그 한계를 제안 문구에 넣는다.
